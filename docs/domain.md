# 领域资料

## 范围

天堂寨康养队伍沿初级 / 中级 / 高级步道分段行进。索道等通行设施可能临时停运，此时已进入山谷的队伍与尚未出发的队伍处境完全不同，需要不同的接续手段：

- **尚未入谷的队伍**：只能看到仍可安全通行的替代连接，带队者确认后改线；
- **已入谷的队伍**：不能改线，只能登记等待（WAIT）、折返（RETURN）或人工护送（ESCORT）决定，决定可更新，被取代的记录保留用于复盘。

路段是否"入谷"由 `segments.in_valley` 标记；队伍当前位置由全部签到事件按现场时间重放得到，而非按上传顺序。

## 角色

- **带队人员**（请求头 `X-Leader-Ref`）：登记本队到 / 离段时间、查询本队可用替代连接、登记改线或入谷处置决定、占用出口与接驳车辆、登记游客名单使用与复盘结果。只能操作自己名下的队伍，游客名单仅所属带队人员可读。
- **维护人员**（请求头 `X-Staff-Role: MAINTENANCE`）：登记基础数据（带队者、队伍、路段、出口、车辆、计划），发布索道状态、路段封闭 / 解封、疏散通道与替代连接，查看全局占用视图，查看复盘汇总。

## 时间与断网补报

所有外部时间必须是带时区偏移的 ISO 8601 字符串。山区断网时，带队者恢复连接后补报签到：

- `occurred_at` 保存**现场原始时间**（逐字留存），`uploaded_at` 保存服务端实际入库时间；
- 两者相差超过 60 秒时标记 `is_backfill = true`；
- 库内另存归一化 UTC 时间用于排序与时间窗比较，原始字符串用于复盘举证。

## 占用互斥

出口（`exits`）与接驳车辆（`shuttles`）按半开时间窗 `[window_start, window_end)` 占用。任一资源与其他队伍仍处于 CLAIMED 状态的窗口重叠时，新的占用请求返回 409；释放（RELEASED）后该时段可再次被占用。同一队伍更新自己的窗口不受自身旧窗口阻挡。

## 复盘

带队者按实际情况登记每队最终如何离开受影响区域（REROUTED / WAITED_AND_RESUMED / TURNED_BACK / ESCORTED），结果必须与该队当前有效的决定一致，并可附出口、接驳车辆与离开时间（同样保留原始时间）。维护人员通过复盘接口查看已交代队伍与尚未交代的队伍清单。

`contracts/entities.json` 保存外部数据的交换字段与业务规则；示例文件 `fixtures/example.json` 只含合成编号，不包含真实个人资料。运行时持久化文件由 `DATABASE_PATH` 决定。
